# OpenMAIC quality review and enhancement priorities

**Review date:** 22 September 2026

**Scope:** current local `production-pilot` working tree, including pre-existing uncommitted additions.

**Decision:** useful educational prototype with passing focused functional checks; hold further rollout until critical dependency findings are addressed. Public/multi-user deployment remains blocked.

## Executive assessment

The strongest part of this version is the no-key Investment Learning Library: six original draft lessons, twelve self-checks and three transparent arithmetic exercises. Its treatment of diversification, drawdowns, fees, sequence risk and AUD/USD is materially better than the earlier generated sample's documented weaknesses.

The main product weakness is beginner orientation. The first screen presents an AI classroom builder and model setup before the ready-made lessons. The main technical concern is current dependency security, not a failing calculator or broken lesson screen.

This review produced this report, fresh build/test artefacts and temporary review logs. It did not implement the proposed app changes or commit, push or merge anything. The prior local changes remain outside the earlier committed PR unless subsequently committed and pushed.

## Findings, ordered by consequence

### 1. Critical: update and triage production dependencies before further rollout

The installed Next.js version is **16.2.11** (`package.json:119`). The current audit and published advisory identify affected Windows-hosted applications; the advisory lists **16.3.3** as the patched 16.x version. This Windows App Router installation makes that finding directly relevant. Successful builds and functional tests do not resolve it.

The four critical audit entries are:

| Package and resolved version | Dependency route | Advisory |
| --- | --- | --- |
| Next.js 16.2.11 | Main app | [Windows-hosted server issue](https://github.com/advisories/GHSA-p293-qw3h-jr36) |
| Next.js 16.2.11 | Main app | [AVIF image optimisation issue](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4) |
| tar 6.1.13 | Main app → copilotkit → tar | [Unbounded archive processing](https://github.com/advisories/GHSA-23hp-3jrh-7fpw) |
| form-data 2.3.3 | Importer → omml2mathml → get-dom → jsdom → request → form-data | [Multipart boundary weakness](https://github.com/advisories/GHSA-fjxv-7rqg-78g4) |

The 232 figure is the audit's production dependency-graph count, including workspace/transitive packages. It is **not** a claim that 232 exploitable vulnerabilities were demonstrated in this app. Reachability and deployment conditions still require triage. In particular, the AVIF finding depends on the image-processing path and underlying libraries; the root app already pins a newer Sharp version, so package-level warnings must not be confused with a reproduced exploit.

The installed `sanitize-html` is 2.17.0 and also appears in current advisories. The reviewed rich-text allow-list excludes the `textarea`/`xmp` options required by [one of those advisories](https://github.com/advisories/GHSA-jxwj-j7wr-gfrw), so that specific warning is not proof of a bypass in this renderer. Updating the dependency is still appropriate.

**Suggested action:** make a reviewed dependency-update change, update the lockfile, review outdated/unused dependency chains, and rerun build, import/export, sanitiser and browser checks. A source search found no direct imports of the unscoped `copilotkit` package; investigate whether it can be removed, rather than assuming it is safe to delete. Avoid indiscriminate forced upgrades.

**Acceptance:** affected direct dependencies patched; every remaining critical/high finding has a documented reachable path or justified disposition; regression tests pass.

### 2. High before shared hosting: identity, isolation and cost control remain incomplete

`lib/persistence/server-auth.ts:1-12,38-53` explicitly provides development-only shared access rather than authenticated ownership. A shared access code is not separate user accounts. `app/api/access-code/verify/route.ts` has no route-local attempt limiter. The reviewed request boundary checks origin and session validity, but does not provide per-user generation quotas.

`next.config.ts:38-60` provides useful baseline headers; its Content Security Policy only sets frame ancestors. It does not provide a complete script/resource policy. The specialised interactive/rendering paths remain a separate review requirement.

**Suggested action:** retain the trusted local scope; before shared hosting add verified user identity, owner-scoped document/asset permissions, attempt limits, generation quotas, spending alerts and recovery-tested storage. Complete the execution-boundary/CSP review. Previously disclosed provider-key rotation remains unverified in this review.

**Acceptance:** one authenticated user cannot read or modify another user's data; billable requests respect limits; a fresh backup restoration succeeds; security tests run against the actual deployment configuration.

### 3. High for content quality: research gating is not yet a durable evidence/approval workflow

The curated browser flow correctly rejects unavailable or empty research and protects restored sessions. However:

- `lib/home/investment-research.ts:7-16` recognises a text marker/opening phrase or a flag. An ordinary custom investment brief is not automatically covered by that rule.
- `lib/home/investment-research.ts:19-40` requires non-empty context and at least one HTTP(S) source, not claim-level relevance, source authority or currentness.
- The check is invoked from the browser preview. The reviewed server outline route (`app/api/generate/scene-outlines-stream/route.ts:287-313,421-440`) accepts optional research context without enforcing the same investment-specific rule.
- The publication/evidence checklist exists as a document, rather than an integrated approval record in the reviewed learning flow.

This is a **quality-control gap**, not a finding that the browser gate is authentication or that every generated lesson is incorrect.

**Suggested action:** use structured course-type metadata, enforce required research server-side before generation, preserve the retrieved evidence set with the lesson, attach material claims to sources/dates, and add Draft → Reviewed → Approved status with reviewer, version and review trigger. Edits after approval should invalidate that approval. Exports should retain status and provenance.

**Acceptance:** direct and restored investment-generation flows obey the same rule; a missing or irrelevant source cannot acquire a verified badge; review records persist and appear in exports.

### 4. Medium: the first screen obscures the best beginner experience

On the inspected 1280 × 585 CSS-pixel viewport, the built-in lesson link began approximately 804px below the top, outside the initial view. The first screen instead displayed “Set up model”, technical classroom wording and generic Python/Fourier/board-game examples. The visible page had no `h1`.

Six icon-only buttons lacked an accessible name in the inspected snapshot/DOM, including Settings and theme. Starter summaries were 11px and some supporting text is specified at 10px. The library itself has clearer headings, labelled controls and a successful mobile-width check; those strengths should be brought onto the homepage.

**Suggested action:** put two clear choices at the top: **Start learning** and **Create a lesson with AI**. Make the former the primary path, explain the app in one sentence, use investing examples, increase important text size, name all controls and check keyboard navigation, focus and contrast.

**Acceptance:** a new user can open the first lesson without scrolling through model setup; all controls have meaningful accessible names; keyboard, 200% zoom, mobile and contrast checks pass.

### 5. Medium: make lessons resumable and assessments more useful

All six lessons appear on one long page (11,173px in the inspected desktop layout). Navigation jumps to sections but there is no visible next-lesson/resume workflow. Quiz answers live in component state and reset on reload (`components/learning/lesson-actions.tsx:6-9,23-25`). Two recognition questions per lesson are useful self-checks, but limited evidence of learning transfer.

**Suggested action:** offer one lesson at a time, Previous/Next controls, a persistent “Continue learning” position, versioned completion status and optional saved answers. Explain local-device storage and offer export/reset. Add short worked scenarios, misconception-specific feedback and an “explain this in your own words” task. Keep completion distinct from financial competence or suitability.

**Acceptance:** reopening resumes the correct lesson/version; content updates do not silently reuse old completion; a learner can apply the idea to a changed example rather than just recognise an answer.

### 6. Medium: improve workbook and sharing usability

The library's download produces a `.md` text workbook (`components/learning/lesson-actions.tsx:10-18`). The download test passes, but many beginners will not know how to open that format. Existing classroom PowerPoint/ZIP exports serve a different purpose.

**Suggested action:** add a clean printable PDF workbook with space for exercise answers, a separately labelled answer section and a draft/review footer. Retain the editable text option. Add a simple “Save or share” explanation that distinguishes a file, a complete classroom backup and a local-only address.

**Acceptance:** the file opens in an ordinary PDF reader, prints legibly, retains source/version/status information and is checked after download. Separately test classroom ZIP restore in a clean profile before describing it as a reliable backup.

## Financial-content assessment

The six built-in drafts appropriately separate education from advice, describe ETFs by underlying exposure rather than label, distinguish systematic and systemic risk, explain stop/leveraged-loss limitations, and label hypothetical calculations. I found no arithmetic discrepancy in the reviewed worked examples:

- A 20% loss needs 25% recovery; a 50% loss needs 100%.
- The two-year withdrawal example gives A$77.50 versus A$82, and A$100 in either ordering without withdrawals.
- A 10% USD return with AUD/USD moving from 0.65 to 0.70 gives about 2.14% in AUD before costs/tax.
- Fee compounding matches the stated end-of-year percentage-fee convention.

Four source routes were retrieved during this review: [ASIC Moneysmart ETFs](https://moneysmart.gov.au/managed-funds-and-etfs/exchange-traded-funds-etfs), [LICs](https://moneysmart.gov.au/managed-funds-and-etfs/listed-investment-companies-lics), [diversification](https://moneysmart.gov.au/how-to-invest/diversification) and [RBA exchange rates](https://www.rba.gov.au/statistics/frequency/exchange-rates.html). Their relevant concepts support the reviewed lessons. This was not an exhaustive link audit or human subject-matter approval; IU/member material was not newly verified. The RBA response's observations ended on 16 September, so it was not used as a live 22 September price source.

The earlier `SAMPLE-CONTENT-REVIEW.md` still records corrections required for the ASX PowerPoint, including risk-per-position wording, tax eligibility and changing market facts. A better prompt or a new library does not itself revise that exported deck. Its contents and visual layout were not freshly re-audited here.

**Content additions worth prioritising:** a plain-language glossary (PDS, TMD, HIN, SRN, hedging), cash/bonds and inflation basics, a visual retirement-withdrawal sequence exercise, and a short evidence checklist beside each lesson. Prefer improving these six lessons before adding a large unreviewed catalogue.

## Recommended delivery order

1. **Security maintenance:** patch/triage dependencies and verify provider-key rotation before resuming wider use.
2. **Beginner release:** clear learner-first homepage, accessible controls, easy PDF workbook and one fully reviewed demonstration lesson.
3. **Learning reliability:** lesson navigation/progress and stronger scenario assessments; tested export/restore.
4. **Publishing discipline:** saved evidence and approval workflow with server-enforced investment research requirements.
5. **Shared service, only if needed:** proper accounts/isolation, budgets, durable storage/workers and operational monitoring.

The existing pilot CI workflow should also run dependency scanning, typechecking, lint and accessibility checks. Its presence as an untracked local file is not evidence that CI has executed. Inspect the broader uncommitted work before any eventual commit or PR update.
